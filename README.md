# 阿简成长实验室

这是「阿简成长实验室」的静态网站项目。

定位：一个普通人利用 AI、数据和长期复盘改变自己的成长记录。网站会长期更新，逐步沉淀为个人成长系统（Growth OS）。

## 页面结构

- `index.html`：首页 / Growth Dashboard
- `projects.html`：我的项目列表
- `archive.html`：成长档案时间轴
- `experiments.html`：实验库分类
- `whitepapers.html`：成长白皮书列表
- `handoffs.html`：项目交接卡列表
- `contact.html`：联系我

## 内容目录

- `projects/`：项目详情
- `archive/`：成长档案详情
- `experiments/`：实验分类详情
- `whitepapers/`：成长白皮书详情
- `handoffs/`：项目交接卡详情

## 数据安全硬规则（禁止破坏）

这是本仓库的最高优先级更新规则，任何后续人工、AI、脚本或自动化更新都必须遵守：

1. **历史数据只允许追加、修正，不允许整库覆盖。** 特别是 `growth-data.js`，禁止用精简版、空模板、新生成版本直接替换现有完整文件。
2. **更新前必须先读取当前线上/主分支原文件，并在现有内容基础上做增量修改。** 不允许凭记忆重新生成整份数据文件。
3. **禁止大规模删除历史记录。** 如果一次更新出现大量删除，尤其是核心数据文件减少数百行、数千行或明显缩小，必须立即停止，不得提交。
4. **所有 SOP、规律、实验、风险、案例、视频数据、账号记录、脚本拆解、项目成果等历史内容必须保留。** 新内容只能叠加到原有结构中。
5. **更新前先检查 diff。** 若删除量明显高于新增量，或核心数据文件体积/行数异常下降，视为高风险更新，必须人工确认后才能继续。
6. **更新失败或结构不确定时，宁可不更新，也不能覆盖旧数据。** 历史数据完整性优先于同步速度。
7. **需要重构时先备份/建分支。** 未验证新版本完整性前，不得直接改动主分支中的完整数据源。
8. **GitHub 历史版本是最后兜底。** 发现数据缺失时优先回退到最近确认完整的提交，再做增量恢复。

> 核心原则：**旧数据不丢、只增量更新；任何“整文件重写”都默认视为危险操作。**

## 后续新增内容

新增一篇成长白皮书：

1. 在 `whitepapers/` 下新增一个详情页。
2. 在 `whitepapers.html` 的列表中新增一条卡片链接。
3. 如有需要，同步更新首页 Growth Dashboard 数量。

新增项目、实验、交接卡同理。
